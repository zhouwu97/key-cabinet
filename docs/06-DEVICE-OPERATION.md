# 智能钥匙自助借还系统：设备操作交互与时序契约 (Device Operation Specification)

> 文档版本：V1.0  
> 状态：正式冻结 (Frozen)  
> 范围：小程序端 UI 呈现 ↔ 业务后台调度 ↔ ESP32 硬件执行的完整时序与错误恢复

---

## 1. 架构原则与职责边界

```text
┌──────────────┐          REST / SSE          ┌──────────────┐          MQTT (QoS 1)         ┌──────────────┐
│  微信小程序   │ ───────────────────────────> │   业务后台    │ ────────────────────────────> │  ESP32 柜机   │
│ (面向普通用户) │ <─────────────────────────── │  (状态机管理) │ <──────────────────────────── │ (步进电机/RFID)│
└──────────────┘                              └──────────────┘                              └──────────────┘
```

1. **小程序端**：只负责采集用户意图、轮询/SSE 接收操作进度、呈现友好中文步骤指示及指导用户动作。不直接向硬件下发 MQTT 指令。
2. **业务后台**：负责校验预约权限、创建 `DeviceOperation` 事务、向 MQTT 下发 `cmd`、订阅接收柜机硬件上报并更新状态机。
3. **柜控硬件 (ESP32)**：负责步进电机定位、电磁锁/舵机开关门、槽位微动开关采样、RFID 芯片读取及状态上报。

## 2. 6 阶段操作步骤与多端映射字典

| 步骤序号 | 步骤标识 (Key) | 中文标题 | 面向用户的操作引导 (User Prompt) | 对应的硬件动作 / MQTT 事件 |
| :---: | :--- | :--- | :--- | :--- |
| **1 / 6** | `INIT` | 身份验证完成 | 系统已核验预约权限，正在连接钥匙柜 | 后台校验成功，生成 Operation |
| **2 / 6** | `PREPARING` | 设备响应就绪 | 钥匙柜已锁定，即将启动机械定位 | MQTT cmd 发送成功，硬件进入 BUSY |
| **3 / 6** | `POSITIONING` | 正在定位钥匙 | 正在将钥匙移动至取钥口，请勿操作柜体 | 步进电机转动对准槽位 (`POSITIONED`) |
| **4 / 6** | `DOOR_OPEN` | 柜门开启 | 柜门已开启，请取走钥匙并在 60 秒内关门 | 电磁锁释放，开门行程开关触发 |
| **5 / 6** | `VERIFYING` | 确认取钥/RFID校验 | 正在确认钥匙离柜 / 校验归还 RFID 芯片 | 微动开关离位 / RFID 读头扫描校验 |
| **6 / 6** | `SUCCESS` | 操作完成 | 钥匙已成功取出 / 归还，借还台账已生效 | 柜门关闭，机械归位，后台事务提交 |

## 3. 异常分支处理与容错机制

### 3.1 用户超时未取/未关门 (60 秒超时)
- **现象**：柜门打开后，用户超过 60 秒未取钥匙或未关闭柜门。
- **硬件动作**：柜机蜂鸣器长鸣报警，超时定时器触发后强制电机复位关门（防夹保护）。
- **上报与状态**：硬件上报 `EVENT_ALARM (DOOR_TIMEOUT)`，操作标记为 `FAILED (E210)`。

### 3.2 归还时放入错误钥匙 (RFID 校验失败)
- **现象**：用户归还钥匙时，插入的 RFID 芯片 UID 与该槽位应还钥匙 UID 不符。
- **硬件动作**：RFID 读头比对失败，语音/蜂鸣提示“钥匙不匹配”，柜门保持或重新弹开，拒绝执行锁死。
- **状态流转**：操作置 `FAILED (E208: RFID_WRONG_KEY)`，借还单保持 `BORROWED` 状态不变。

### 3.3 客户端掉线与恢复 (Operation Recovery)
- **机制**：若用户在操作执行过程中关闭小程序或网络中断，后台状态机仍持续跟随硬件事件驱动流转。
- **恢复**：用户重新打开小程序时，首页通过 `activeOperation` 查询发现存在进行中事务，顶部置顶呈现「未完成设备操作」呼吸横幅，点击直接恢复进入实时步进进度页。
